# Module acceptance checklist

For every line mark `PASS`, `FAIL`, `BLOCKED` or `N/A — reason`, with evidence.

- [ ] Business rules approved and requirement IDs mapped
- [ ] Backend behavior implemented
- [ ] Database constraints, transactions and migration tested
- [ ] API contracts and versioning updated
- [ ] Frontend and accessibility requirements verified
- [ ] Authentication and server-side authorization verified
- [ ] Audit and financial controls verified
- [ ] External integrations and capability limits documented
- [ ] Concurrency/inventory correctness tested
- [ ] Error handling, retries, unknown outcomes and recovery tested
- [ ] Offline behavior tested where applicable
- [ ] Unit, integration, contract and E2E tests run
- [ ] Security review completed; findings dispositioned
- [ ] Performance/failure tests completed where applicable
- [ ] Logs, metrics, traces, alerts and dashboards updated
- [ ] Technical/support/runbook documentation updated
- [ ] Deployment configuration, secrets, migration and rollback reviewed
- [ ] Source-of-truth reconciliation complete

A UI demo, screenshot, browser recording or generated test file cannot independently satisfy this checklist.

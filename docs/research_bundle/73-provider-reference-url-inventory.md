## 4. Integration evidence checklist per URL

For each endpoint/page the IDE agent proposes to implement, record:

- Current URL, title/product name, API style and version.
- Last-updated date visible on source, date accessed and whether source is current, Beta, deprecated or unavailable.
- Required credential, scope, agency/PCC/merchant account and production entitlement.
- Request and response schema versions; required/conditional fields; enum/status definitions; idempotency semantics.
- Workflow dependency (must search first, revalidate, book, fulfill, retrieve, etc.).
- Error/rate-limit/retry rules and expiry/time limit behavior.
- Allowed data use, display/branding rights, retention and PII considerations.
- Mock/contract/sandbox/production test evidence separately labeled.
- Remaining questions and accountable owner.

A URL inventory is not an API implementation plan on its own; Documents 67–72 define the workflow, safety and capability gates.
